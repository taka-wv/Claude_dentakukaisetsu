1この電卓でできること

このプログラムは、Windows フォームで作った電卓です。ボタンを押したときの処理は、すべて Form1 クラス（Form1.cs）の中に書かれています。

  • 四則演算（＋ − × ÷）を「3+4×2…」のように続けて入力できる
  • 計算は押した順に左から行う（×÷を先に計算するルールはない）
  • 小数点（0.5 など）と、マイナスの数（3×-2 など）が入力できる
  • 1つの数は最大 8桁。答えも8桁に収まるように四捨五入する
  • 0で割ったときと、答えが8桁をこえたときはエラー表示になる
  • ［C］で1文字消す、［CA］ですべてクリア

画面には表示欄が2つあります。

場所コントロールの名前表示するもの
上の段（小さい文字）expressionLabelもう確定した式（例：3+4×）
下の段（大きい文字）window今入力している数、小計、答え、エラーメッセージ
このページで扱うのは Form1.cs だけです。ボタンや表示欄を画面に並べるコードは、Visual Studio が自動で作る Form1.Designer.cs に入っています（今回の資料には含まれていません）。「b1 ボタンがクリックされたら b1_Click を呼ぶ」という結び付けも、ふつうはそちらに次のような形で書かれています。 
this.b1.Click += new System.EventHandler(this.b1_Click);
フォームのデザイン画面でボタンをダブルクリックすると、この行と空の b1_Click メソッドが自動で作られます。

2全体の流れ：ボタンを押すと何が起きる？

どのボタンも、だいたい同じ道を通ります。

① ボタンを押す例：［3］ボタン
→
② 入口のメソッドボタンごとの 〇〇_Click。例：b3_Click
→
③ 共通の処理AppendDigit、OperatorPressed など。ここで値を書き換える
→
④ 画面を作り直すShowDisplay が値を見て、上下の段に表示

ボタンと、呼ばれるメソッドの対応は次のとおりです。

ほかに、裏方として使われるメソッドがあります：ShowDisplay（画面の更新）、ResetAll（全部リセット）、ShowError（エラー表示）、FormatNumber（数を表示用の文字にする）、CountDigits・CountIntegerDigits（桁数を数える）。

ポイント：同じ処理は1か所にまとめる 数字ボタンは10個ありますが、やることは「押された数字をつなげる」だけで同じです。そこで b0_Click〜b9_Click は、ボタンの文字（this.b3.Text なら "3"）を AppendDigit に渡すだけにしています。こうすると、直したいときも AppendDigit の1か所を直せば済みます。演算子ボタンと OperatorPressed の関係も同じです。
ポイント：画面は「値から作り直す」 画面に文字を書き込むのは、基本的に ShowDisplay だけです（例外はエラーのときの ShowError）。各メソッドはまず変数の値を書き換え、最後に ShowDisplay を呼んで、今の値から画面を作り直します。逆に、途中で return して ShowDisplay を呼ばなかったときは、画面は変わりません。

3電卓が覚えている5つの値

電卓は「ここまでに何が押されたか」を覚えておく必要があります。そのための変数が、クラスの先頭（L18〜L32）にある5つのフィールドです。このページでは、それぞれに色を付けて区別します。

名前型役割最初の値入る値の例
totaldecimalここまでの計算結果（小計）0「3+4×」まで押すと 7
operationstring最後に押された演算子。まだ押していなければ空文字"""+" "-" "×" "÷"
expressionstring上の段に表示する、確定した式"""3+4×"
currentInputstring今入力している途中の数"""12" "-" "0."
justCalculatedbool［＝］を押した直後（答えが出ている状態）なら truefalsetrue / false

フィールドは、処理が終わっても値が残る

メソッドの中で宣言した変数（たとえば OperatorPressed の中の number や error）は、そのメソッドが終わると消えてしまいます。一方、メソッドの外（クラスの中）に書いたフィールドは、フォームが開いている間ずっと値が残ります。だから「さっき押した＋」や「ここまでの小計」を、次のボタンを押したときに使えるのです。

なぜ currentInput は数（decimal）ではなく文字列（string）？

入力の途中には、"0." や "-" のように「まだ数として完成していない形」があります。数の型ではこれを表せません（"0." を数にすると 0 になり、点が消えてしまう）。そこで入力中は文字列のまま持っておき、計算するときだけ decimal.TryParse で数に変換しています。

なぜ double ではなく decimal？

double はコンピューターの中で2進数として数を持つため、0.1 + 0.2 が 0.30000000000000004 のようにずれることがあります。decimal は10進数として持つので、0.1 + 0.2 はきちんと 0.3 になります。そのかわり扱える範囲は約28〜29桁までです。お金の計算や電卓のように「見たとおりの10進数で正確に計算したい」ときに向いています。

決まった値（定数）

const を付けた値は、プログラムの途中で書き換えられません。数字やメッセージを直接書く代わりに名前を付けておくと、意味が分かりやすくなり、変えたいときも1か所を直すだけで済みます。

名前値使われ方
MaxExpressionLength20上の段に表示できる最大の文字数。これを超えたら先頭を「…」にする
MaxDigits81つの数に使える最大の桁数。入力できる桁数と、答えを表示する桁数の両方に使う
DivideByZeroMessage"(^o^)0ﾜﾙﾅ"0で割ったときのメッセージ
OverflowMessage"(^o^)ｹﾀｱﾌﾚ"答えが8桁をこえたときのメッセージ

4いちばん大事な仕組み：演算子は「1つ遅れて」計算される

［＋］を押した瞬間には、次に何の数が来るかまだ分かりません。だから、その場では計算できません。そこでこの電卓は、押された演算子をいったん operation に覚えておき、次の演算子か［＝］が押されたときに、覚えていた演算子で計算します。

「3 + 4 × 2 =」と押したときの様子です。

押したボタン3+4×2=
その時に行う計算—total = 3
（最初の数）		—3 + 4 = 7
（覚えていた ＋）		—7 × 2 = 14
（覚えていた ×）
operation に入る値"""+""+""×""×"""
（リセット）

だから 3+4×2 の答えは 14 になります。算数のルール（×を先に計算）なら 11 ですが、この電卓は一般的な電卓と同じく「押した順」に計算します。

コードでは、OperatorPressed の中のこの順番が、この仕組みを作っています。

string error = Calculate(number);   // ① 先に、覚えていた演算子（operation）で計算する  … L225
   ︙
expression = expression + currentInput + newOperation;
operation = newOperation;           // ② そのあとで、新しく押された演算子を覚える  … L241

もし①と②の順番が逆だと、新しく押した演算子で計算してしまい、「3+4×」の時点で 3×4 になってしまいます。Calculate の中で使っている operation は、前に押した演算子だという点が大切です。

    287 private string Calculate(decimal number)
    288 {
    289 // try の中でエラー（例外）が起きると、catch に飛ぶ
    290 // → アプリが落ちずに、エラー表示にできる
    291 try
    292 {
    293 if (operation == "")
    294 {
    295 // 最初の数のときは、そのまま覚えるだけ
    296 total = number;
    297 }
    298 else if (operation == "+")
    299 {
    300 total = total + number;
    301 }
    302 else if (operation == "-")
    303 {
    304 total = total - number;
    305 }
    306 else if (operation == "×")
    307 {
    308 total = total * number;
    309 }
    310 else if (operation == "÷")
    311 {
    312 // 0 で割るとエラーになるので、先に確認する
    313 if (number == 0)
    314 {
    315 return DivideByZeroMessage;
    316 }
    317 total = total / number;
    318 }
    319 }
    320 catch (OverflowException)
    321 {
    322 // decimal で扱える範囲（約29桁）を超えたとき
    323 // ※MaxDigits が 10 のままなら起きないが、MaxDigits を大きくしたときのための安全策
    324 return OverflowMessage;
    325 }
    326
    327 // 整数部分が表示できる桁数（MaxDigits）を超えたら、桁あふれにする
    328 // 例：9999999999.6 は四捨五入すると 10000000000（11桁）になるので、丸めてから数える

    330 if (CountIntegerDigits(rounded) > MaxDigits)
    331 {
    332 return OverflowMessage;
    333 }
    334
    335 return "";
    336 }

    2. currentInput を数に変換。"-" だけのように変換できなければ何もしない L217
    3. Calculate で、覚えていた演算子を使って計算。エラーなら ShowError L225
    4. "5." のように点で終わっていたら、点を消す（式が "5.+" にならないように） L234

    最後の計算をして、答えを出す
    1. 演算子がまだ押されていなければ、何もしない L251
    2. "3+" の直後のように最後の数がなければ、何もしない L258
    3. Calculate で計算。エラーなら ShowError L264

    答えが currentInput に入っているので、続けて演算子を押すと、答えを最初の数として計算を続けられます。

    Calculate(decimal number)

    total と number を、覚えていた演算子で計算して total に入れる
    1. operation の中身で分かれる。""（最初の数）なら total = number、"+" なら total + number … L293
    2. 割り算のときは、割る前に number が 0 かを確認。0 なら DivideByZeroMessage を返す L313
    3. 計算全体を try で囲み、decimal の範囲を超えた（OverflowException）ときも落ちないようにしている L320
    4. total を整数に四捨五入して、8桁を超えたら OverflowMessage を返す L329
    5. うまくいけば ""（空文字）を返す L335

    戻り値は「エラーメッセージ、または空文字」です。呼ぶ側は error != "" でエラーかどうかを判断し、メッセージをそのまま ShowError に渡します。

    9よくある疑問

    ［＝］を続けて押すとどうなる？
    2回目以降は何も起きません。1回目の［＝］の最後に ResetAll で operation が "" に戻っているので、L251 で return します。前の計算を繰り返す機能はありません。
    「5」だけ入力して［＝］を押すと？
    何も起きません。演算子がまだないので、計算するものがありません（L251）。
    「3+」の後に［×］を押すと？
    演算子が入れ替わって、式は "3×" になります（L208）。
    「3+」の後に［-］を押すと？
    入れ替えではなく、マイナスの数の入力開始になります（L201）。続けて 2 を押せば「3+-2」です。そのため、「+」を「-」に入れ替えることはできません（「3+-2」と「3-2」は同じ答えなので、計算には困りません）。
    「-」だけ入力した状態で［×］を押すと？
    何も起きません。"-" は数に変換できないので、L217 で return します。［C］で "-" を消せば、演算子の入れ替えができます。
    答えが出た後に、数字・演算子・［C］を押すと？
    数字なら新しい計算が始まります（justCalculated が true なので ResetAll）。演算子なら、答えを最初の数として計算を続けます。［C］なら答えの最後の1文字が消え、そのまま続きを入力できます。
    1÷3＝ の答えに ×3＝ をすると、なぜ 1 にならない？
    ［＝］を押すと、答えは8桁に丸めた文字列 "0.3333333" として currentInput に入ります。続きの計算はこの丸めた値で行うので、0.3333333×3 ＝ 0.9999999 になります。一方、［＝］を挟まずに「1÷3×3＝」と押すと、total には28桁の 0.3333…が残ったまま計算されるので、答えは 1 になります。
    エラーが出た後はどうなっている？
    ShowError の中で ResetAll しているので、中身は起動直後と同じです。数字を押せば新しい計算が始まり、［C］や［CA］を押すと下の段が "0" に戻ります。
    9桁目の数字を押すと？
    AppendDigit の L128 で return するので、何も変わりません。ShowDisplay も呼ばれないので、画面もそのままです。
